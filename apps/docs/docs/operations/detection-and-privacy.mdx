## How Detection Works

The plugin has a built-in feature that notifies the author when it detects anomalies in <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensor</Terminology> states and <Terminology title="The Home tile you use to arm and disarm" to="/docs/reference/terminology#accessories-and-arming">panel</Terminology> statuses.

- Notifications are triggered when a status is encountered that the plugin does not yet recognize.
- Undocumented statuses are the primary trigger, since the author needs the raw values to add support for new devices and states.
- A report goes out once per new finding while the plugin runs, and only after the plugin confirms it is the latest release. Outdated installations, or a failed version check, send nothing.
- Each <Terminology title="A redacted note to the author about unknown devices" to="/docs/reference/terminology#troubleshooting-and-maintenance">report</Terminology> goes out as two requests to the same address. The first gets a one-time pass, and the second sends the report with it, so reports that don't come from the plugin are turned away.

The plugin adheres to the [verified Homebridge plugin](https://github.com/homebridge/homebridge/wiki/verified-Plugins#verified-plugins) requirements, so it does not track your usage. Detection reports are the only data it sends.

## Privacy Redaction

Known identifying fields in a <Terminology title="A redacted note to the author about unknown devices" to="/docs/reference/terminology#troubleshooting-and-maintenance">report</Terminology> are redacted before the information leaves your system. Raw portal HTML in a parser anomaly report is the exception (see [Raw HTML Reports](#raw-html-reports)).

Redacted fields are replaced with the literal string `*** REDACTED FOR PRIVACY ***`, because these values are not needed to improve the plugin.

| Field type     | Description                                                                                                                                                                                                                                                                                                                                     |
|----------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| IP addresses   | Broadband, device, and router LAN/WAN addresses.                                                                                                                                                                                                                                                                                                |
| MAC addresses  | Broadband and device hardware addresses.                                                                                                                                                                                                                                                                                                        |
| Serial numbers | Hardware serial numbers reported by the <Terminology title="The ADT Pulse gateway, shown in Home by default" to="/docs/reference/terminology#accessories-and-arming">gateway</Terminology>.                                                                                                                                                     |
| Update times   | Last and next scheduled update timestamps.                                                                                                                                                                                                                                                                                                      |
| Master code    | The <Terminology title="The Home tile you use to arm and disarm" to="/docs/reference/terminology#accessories-and-arming">security panel</Terminology>'s master access code shown on the <Terminology title="The ADT website the plugin talks to for everything" to="/docs/reference/terminology#adt-pulse-and-homebridge">portal</Terminology>. |
| Session tokens | The `sat` authentication token embedded in scraped portal requests.                                                                                                                                                                                                                                                                             |

### Privacy Warnings

A reminder appears each time you might send a <Terminology title="A redacted note to the author about unknown devices" to="/docs/reference/terminology#troubleshooting-and-maintenance">report</Terminology>, so the redaction behavior is never a surprise.

- A privacy notice appears when you use the included <Terminology title="Command-line tools to test the portal connection" to="/docs/reference/terminology#troubleshooting-and-maintenance">scripts</Terminology> and when the plugin starts, and a warning is logged when the plugin is about to notify the author.
- The reminder restates that identifying fields are redacted before any information is sent.

## Example Report

Here is an example of the information the author sees when the plugin detects unknown statuses from the <Terminology title="The ADT Pulse gateway, shown in Home by default" to="/docs/reference/terminology#accessories-and-arming">gateway</Terminology>.

```json
{
  "communication": {
    "broadbandConnectionStatus": "Active",
    "cellularConnectionStatus": "N/A",
    "cellularSignalStrength": "N/A",
    "primaryConnectionType": "Broadband"
  },
  "manufacturer": "ADT Pulse Gateway",
  "model": "PGZNG1",
  "network": {
    "broadband": {
      "ip": "*** REDACTED FOR PRIVACY ***",
      "mac": "*** REDACTED FOR PRIVACY ***"
    },
    "device": {
      "ip": "*** REDACTED FOR PRIVACY ***",
      "mac": "*** REDACTED FOR PRIVACY ***"
    },
    "router": {
      "lanIp": "*** REDACTED FOR PRIVACY ***",
      "wanIp": "*** REDACTED FOR PRIVACY ***"
    }
  },
  "serialNumber": "*** REDACTED FOR PRIVACY ***",
  "status": "Online",
  "update": {
    "last": "*** REDACTED FOR PRIVACY ***",
    "next": "*** REDACTED FOR PRIVACY ***"
  },
  "versions": {
    "firmware": "1.0.0-9",
    "hardware": "HW=2, BL=1.0.0, PL=1.0.0, SKU=12345"
  }
}
```

The unredacted fields, such as connection status, model, firmware, and hardware version, are the values that describe the undocumented status itself.

## Raw HTML Reports

In some scenarios, the plugin identifies anomalies while parsing <Terminology title="The ADT website the plugin talks to for everything" to="/docs/reference/terminology#adt-pulse-and-homebridge">portal</Terminology> data rather than reading a known status.

- These <Terminology title="A redacted note to the author about unknown devices" to="/docs/reference/terminology#troubleshooting-and-maintenance">reports</Terminology> may contain raw HTML data, which is left out of your local logs.
- The raw HTML sent to the author remains unfiltered, so undocumented <Terminology title="The ADT website the plugin talks to for everything" to="/docs/reference/terminology#adt-pulse-and-homebridge">portal</Terminology> layouts can be updated promptly.

## Opting Out

You can prevent this functionality by blocking the URL that the plugin uses to notify the author.

:::warning
If you block the notification URL, the author will not be able to offer assistance or support, since the plugin can no longer report the undocumented statuses it needs to diagnose issues.
:::
