Complete Away, Stay, and Night arm requests automatically through <Terminology title="Arms anyway by bypassing open or active sensors" to="/docs/reference/terminology#accessories-and-arming">force arming</Terminology> whenever the portal shows its "Arm Anyway" prompt, such as for active motion or open <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensors</Terminology>.

## How Force Arming Works

The Home app relies on the <Terminology title="The protocol the Home app uses to talk to accessories" to="/docs/reference/terminology#adt-pulse-and-homebridge">HAP</Terminology> protocol to establish arm states, and that protocol expects an arm request to succeed. To satisfy it, the plugin <Terminology title="Arms anyway by bypassing open or active sensors" to="/docs/reference/terminology#accessories-and-arming">force arms</Terminology> by selecting "Arm Anyway" whenever the portal shows that prompt, such as for active motion or open <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensors</Terminology>.

<Terminology title="Arms anyway by bypassing open or active sensors" to="/docs/reference/terminology#accessories-and-arming">Force arming</Terminology> applies to every arm state exposed through HomeKit:

- **Arm Away** — Arms the system while treating triggering <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensors</Terminology> as <Terminology title="Arms anyway by bypassing open or active sensors" to="/docs/reference/terminology#accessories-and-arming">force-armed</Terminology>.
- **Arm Stay** — Arms the system while treating triggering <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensors</Terminology> as <Terminology title="Arms anyway by bypassing open or active sensors" to="/docs/reference/terminology#accessories-and-arming">force-armed</Terminology>.
- **Arm Night** — Arms the system while treating triggering <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensors</Terminology> as <Terminology title="Arms anyway by bypassing open or active sensors" to="/docs/reference/terminology#accessories-and-arming">force-armed</Terminology>.

## This Behavior Cannot Be Disabled

<Terminology title="Arms anyway by bypassing open or active sensors" to="/docs/reference/terminology#accessories-and-arming">Force arming</Terminology> is always on. Disabling it is not possible, because doing so would result in arming failures without alert notifications.

:::warning
<Terminology title="Arms anyway by bypassing open or active sensors" to="/docs/reference/terminology#accessories-and-arming">Force arming</Terminology> is a fixed behavior with no configuration option to turn it off. There is no field in `config.schema.json` that controls it.
:::

## Check Your Sensors Before Arming

If you are concerned about arming with active motion or open <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensors</Terminology>, check the status of the <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensors</Terminology> in your home before you arm the system.

To review which <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensors</Terminology> need attention:

1. Open the Home app.
2. Tap the dotted circle (`...`) located on the top right of the screen.
3. View the <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensors</Terminology> that require attention and resolve those issues.

Resolving flagged <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensors</Terminology> first lets you arm with everything in the expected state, rather than relying on the <Terminology title="Arms anyway by bypassing open or active sensors" to="/docs/reference/terminology#accessories-and-arming">force arm</Terminology> to complete the request.

## Automation Considerations

If you have set up automation that arms the system, you acknowledge that <Terminology title="Arms anyway by bypassing open or active sensors" to="/docs/reference/terminology#accessories-and-arming">force arming</Terminology> will happen. You accept the risk of the system not completely arming itself when a <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensor</Terminology> is active or open at the time of the request.

:::info
Arm Night is only available through the <Terminology title="The Home tile you use to arm and disarm" to="/docs/reference/terminology#accessories-and-arming">panel</Terminology> itself on ADT Pulse systems, but you can still place your system into Arm Night mode with this plugin. See [Arm Night Support](/docs/arming/arm-night/) for details.
:::
