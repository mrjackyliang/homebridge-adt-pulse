Reference every <Terminology title="The Homebridge plugin type; this one is ADTPulse" to="/docs/reference/terminology#plugin-configuration">platform</Terminology> config field, its type, defaults, and accepted values as defined by the plugin schema.

## Platform Block

Every setting lives inside a single <Terminology title="The Homebridge plugin type; this one is ADTPulse" to="/docs/reference/terminology#plugin-configuration">platform</Terminology> object under the top-level `platforms` array in your Homebridge `config.json`. The `platform` value identifies the plugin and must be exactly `ADTPulse`.

The table below lists the fields the <Terminology title="The Homebridge plugin type; this one is ADTPulse" to="/docs/reference/terminology#plugin-configuration">platform</Terminology> accepts, in schema order.

| Field         | Type       | Required | Default     | Description                                                                                                                                                                                             |
|---------------|------------|:--------:|-------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `platform`    | `string`   |   Yes    | -           | Plugin identifier. Must be `ADTPulse`.                                                                                                                                                                  |
| `name`        | `string`   |   Yes    | `ADT Pulse` | Display name used for identification, such as in Homebridge logs.                                                                                                                                       |
| `subdomain`   | `string`   |   Yes    | `portal`    | <Terminology title="The ADT website the plugin talks to for everything" to="/docs/reference/terminology#adt-pulse-and-homebridge">Portal</Terminology> region. See [Subdomain](#subdomain).                                   |
| `username`    | `string`   |   Yes    | -           | Username you use to log in to the <Terminology title="The ADT website the plugin talks to for everything" to="/docs/reference/terminology#adt-pulse-and-homebridge">portal</Terminology>.                                     |
| `password`    | `string`   |   Yes    | -           | Password you use to log in to the <Terminology title="The ADT website the plugin talks to for everything" to="/docs/reference/terminology#adt-pulse-and-homebridge">portal</Terminology>.                                     |
| `fingerprint` | `string`   |   Yes    | -           | Device <Terminology title="An ID for your device that the portal needs to log in" to="/docs/reference/terminology#setup-and-login">fingerprint</Terminology> required for two-factor authentication. |
| `mode`        | `string`   |   Yes    | `normal`    | <Terminology title="Run normally, pause the plugin, or reset its accessories" to="/docs/reference/terminology#plugin-configuration">Operational mode</Terminology>. See [Mode](#mode).                                 |
| `speed`       | `number`   |   Yes    | `1`         | Synchronization speed. See [Speed](#speed).                                                                                                                                                             |
| `options`     | `string[]` |    No    | `[]`        | Advanced feature toggles. See [Options](#options).                                                                                                                                                      |
| `sensors`     | `object[]` |    No    | `[]`        | <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">Sensors</Terminology> to expose to HomeKit. See [Sensors](#sensors).                               |

## Name

The `name` field is a free-form string used mainly for identification, such as in Homebridge logs.

| Constraint | Value         |
|------------|---------------|
| Type       | `string`      |
| Minimum    | 1 character   |
| Maximum    | 50 characters |
| Default    | `ADT Pulse`   |

## Subdomain

The `subdomain` field selects the ADT Pulse <Terminology title="The ADT website the plugin talks to for everything" to="/docs/reference/terminology#adt-pulse-and-homebridge">portal</Terminology> region tied to your account.

| Value       | Region        | Description                                   |
|-------------|---------------|-----------------------------------------------|
| `portal`    | United States | Default. Use if you are subscribed in the US. |
| `portal-ca` | Canada        | Use if you are subscribed in Canada.          |

The ability to switch regions is determined by the ADT region you are subscribed to. See [Portal Region](/docs/getting-started/portal-region/) for more detail.

## Username and Password

The `username` and `password` fields hold the credentials you use to log in to the <Terminology title="The ADT website the plugin talks to for everything" to="/docs/reference/terminology#adt-pulse-and-homebridge">portal</Terminology>.

| Field      | Type     | Minimum     | Maximum        |
|------------|----------|-------------|----------------|
| `username` | `string` | 1 character | 100 characters |
| `password` | `string` | 1 character | 300 characters |

## Fingerprint

The `fingerprint` field holds the device <Terminology title="An ID for your device that the portal needs to log in" to="/docs/reference/terminology#setup-and-login">fingerprint</Terminology> that ADT Pulse requires during login once two-factor authentication is enabled.

| Constraint | Value            |
|------------|------------------|
| Type       | `string`         |
| Minimum    | 1 character      |
| Maximum    | 10240 characters |

Starting from `v3.3.5`, the <Terminology title="An ID for your device that the portal needs to log in" to="/docs/reference/terminology#setup-and-login">fingerprint</Terminology> is created by the built-in Homebridge <Terminology title="Logs into the portal for you and writes the plugin config" to="/docs/reference/terminology#setup-and-login">setup wizard</Terminology>. Re-run the wizard and save its configuration to replace an old value.

See [Device Fingerprint](/docs/getting-started/fingerprint/) for the full walkthrough.

## Mode

The `mode` field controls how the plugin runs.

| Value    | Title  | Description                                             |
|----------|--------|---------------------------------------------------------|
| `normal` | Normal | Default. Regular operation.                             |
| `paused` | Paused | Pauses the plugin so all devices become non-responsive. |
| `reset`  | Reset  | Resets the plugin, removing associated accessories.     |

Debug mode is enabled only when Homebridge debug mode is on; there is no separate setting for it.

:::danger
Setting `mode` to `reset` starts a countdown of approximately 40 seconds before all accessories related to this plugin are removed.
:::

See [Operational Mode](/docs/configuration/operational-mode/) for the full behavior of each <Terminology title="Run normally, pause the plugin, or reset its accessories" to="/docs/reference/terminology#plugin-configuration">mode</Terminology>.

## Speed

The `speed` field adjusts the interval at which the plugin fires <Terminology title="How the plugin learns something changed on the portal" to="/docs/reference/terminology#portal-sessions">sync check</Terminology> and <Terminology title="Keeps your portal login from timing out" to="/docs/reference/terminology#portal-sessions">keep-alive</Terminology> signals, which can ease network load and CPU usage on older hardware.

| Value  | Title                  | Description                  |
|--------|------------------------|------------------------------|
| `1`    | Normal Speed (1x)      | Default. Fires every second. |
| `0.75` | Moderate Speed (0.75x) | Slower firing interval.      |
| `0.5`  | Slower Speed (0.5x)    | Slower firing interval.      |
| `0.25` | Slowest Speed (0.25x)  | Slowest firing interval.     |

Any value other than `1` may result in slower device updates and produces a startup warning that cannot be disabled. See [Synchronization Speed](/docs/configuration/synchronization-speed/) for guidance on when to slow it down.

## Options

The `options` field is an array of feature toggles that deactivate specific plugin behaviors. Leave it empty (`[]`) to keep all functionality enabled.

| Value                       | Title                                | Description                                                                                                                                                                                                                                                          |
|-----------------------------|--------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `disableAlarmRingingSwitch` | Disable "Alarm Ringing" switch       | Removes the switch used to silence a ringing alarm.                                                                                                                                                                                                                  |
| `ignoreSensorProblemStatus` | Ignore "Sensor Problem" Panel Status | Stops "Sensor Problem" and "Sensor Problems" <Terminology title="The Home tile you use to arm and disarm" to="/docs/reference/terminology#accessories-and-arming">panel</Terminology> statuses from counting as an active alarm. Fault and tamper still report them. |

A non-empty `options` array produces a startup warning that cannot be disabled. See [Advanced Options](/docs/configuration/advanced-options/) for the caveats of each toggle.

## Sensors

The `sensors` field is an array of objects, one per <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensor</Terminology> you want to expose to HomeKit. Each <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensor</Terminology> is read-only, and you must declare every <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensor</Terminology> explicitly.

| Constraint | Value      |
|------------|------------|
| Type       | `object[]` |
| Minimum    | 0 items    |
| Maximum    | 147 items  |
| Default    | `[]`       |

The maximum of 147 accounts for 3 reserved slots (the <Terminology title="The ADT Pulse gateway, shown in Home by default" to="/docs/reference/terminology#accessories-and-arming">gateway</Terminology>, <Terminology title="The Home tile you use to arm and disarm" to="/docs/reference/terminology#accessories-and-arming">security panel</Terminology>, and <Terminology title="Turn it off to silence a ringing alarm" to="/docs/reference/terminology#accessories-and-arming">alarm ringing switch</Terminology>). Z-Wave accessories are not supported.

### Sensor Fields

Each object in the `sensors` array accepts the following fields.

| Field     | Type     | Required | Description                                                                                                                                                                                                                                                                                                                        |
|-----------|----------|:--------:|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `name`    | `string` |    No    | Optional display name to differentiate the <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensor</Terminology> from the name ADT technicians assigned.                                                                                                                       |
| `adtName` | `string` |   Yes    | Exact name shown under the "Name" column in the <Terminology title="The ADT website the plugin talks to for everything" to="/docs/reference/terminology#adt-pulse-and-homebridge">portal</Terminology> <Terminology title="The portal page showing each sensor's name, zone, and type" to="/docs/reference/terminology#plugin-configuration">"System" tab</Terminology>. |
| `adtZone` | `number` |   Yes    | Exact zone shown under the "Zone" column in the <Terminology title="The ADT website the plugin talks to for everything" to="/docs/reference/terminology#adt-pulse-and-homebridge">portal</Terminology> <Terminology title="The portal page showing each sensor's name, zone, and type" to="/docs/reference/terminology#plugin-configuration">"System" tab</Terminology>. |
| `adtType` | `string` |   Yes    | <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">Sensor</Terminology> type shown under the "Device Type" column. See [Sensor Types](#sensor-types).                                                                                                                            |

Field constraints:

- `name` can be omitted or left blank to use an ADT-derived display name. A custom name accepts 2 to 50 characters, must start and end with a letter or number, and cannot contain emojis or unsupported symbols.
- `adtName` accepts 1 to 100 characters.
- `adtZone` accepts a number from 1 to 99.

### Sensor Types

The `adtType` field must match one of the supported <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensor</Terminology> types below.

| Value         | Sensor Type                                        |
|---------------|----------------------------------------------------|
| `co`          | Carbon Monoxide Detector                           |
| `doorWindow`  | Door/Window Sensor, Door Sensor, Window Sensor     |
| `fire`        | Fire (Smoke/Heat) Detector                         |
| `flood`       | Water/Flood Sensor                                 |
| `glass`       | Glass Break Detector                               |
| `heat`        | Heat (Rate-of-Rise) Detector                       |
| `motion`      | Motion Sensor, Motion Sensor (Notable Events Only) |
| `shock`       | Shock Sensor                                       |
| `temperature` | Temperature Sensor                                 |

See [Sensors and Zones](/docs/configuration/sensors-and-zones/) for how to find these values, and [Supported Devices](/docs/getting-started/supported-devices/) for what each type maps to in HomeKit.

## Full Example

This example shows a complete <Terminology title="This plugin's settings object in config.json" to="/docs/reference/terminology#plugin-configuration">platform block</Terminology> with a single door/window <Terminology title="A portal device you list in config so it shows up in Home" to="/docs/reference/terminology#plugin-configuration">sensor</Terminology>.

```json title="config.json"
{
  "platforms": [
    {
      "platform": "ADTPulse",
      "name": "ADT Pulse",
      "subdomain": "portal",
      "username": "user@example.com",
      "password": "Mys7r0nG!P@ssw0rd",
      "fingerprint": "VGhpc0lzQVNlY3VyZVBhc3N3b3JkMTIzIQ==",
      "mode": "normal",
      "speed": 1,
      "options": [],
      "sensors": [
        {
          "name": "Family Room Couch Window 1",
          "adtName": "Family Room Window (99)",
          "adtZone": 99,
          "adtType": "doorWindow"
        }
      ]
    }
  ]
}
```

For a task-oriented walkthrough of these fields, see [Configuration](/docs/getting-started/configuration/).
