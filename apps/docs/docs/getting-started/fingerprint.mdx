Generate the device <Terminology title="An ID for your device that the portal needs to log in" to="/docs/reference/terminology#setup-and-login">fingerprint</Terminology> that ADT Pulse requires for login once two-factor authentication is enabled on your account.

## Why the Fingerprint Is Needed

Since the introduction of two-factor authentication, a device <Terminology title="An ID for your device that the portal needs to log in" to="/docs/reference/terminology#setup-and-login">fingerprint</Terminology> has become a necessity during login.

The <Terminology title="The ADT website the plugin talks to for everything" to="/docs/reference/terminology#adt-pulse-and-homebridge">portal</Terminology> ties this <Terminology title="An ID for your device that the portal needs to log in" to="/docs/reference/terminology#setup-and-login">fingerprint</Terminology> to <Terminology title="The one-time code step that registers a trusted device" to="/docs/reference/terminology#setup-and-login">a trusted device</Terminology>, which lets the plugin sign in on your behalf without repeatedly prompting for a verification code.

## Creating the Fingerprint

Starting from `v3.3.5`, you no longer need an external tool to create the <Terminology title="An ID for your device that the portal needs to log in" to="/docs/reference/terminology#setup-and-login">fingerprint</Terminology>. The dedicated Homebridge <Terminology title="Logs into the portal for you and writes the plugin config" to="/docs/reference/terminology#setup-and-login">setup wizard</Terminology> generates it for you.

:::tip
Because the <Terminology title="Logs into the portal for you and writes the plugin config" to="/docs/reference/terminology#setup-and-login">setup wizard</Terminology> creates the <Terminology title="An ID for your device that the portal needs to log in" to="/docs/reference/terminology#setup-and-login">fingerprint</Terminology>, you do not have to make one by hand. Run <Terminology title="Logs into the portal for you and writes the plugin config" to="/docs/reference/terminology#setup-and-login">the wizard</Terminology> from the plugin's configuration screen in the <Terminology title="The web page where you install and set up Homebridge plugins" to="/docs/reference/terminology#adt-pulse-and-homebridge">Homebridge Config UI</Terminology>.
:::

## Browser Profile and Trusted Device Name

The wizard creates a desktop browser profile using current Stable release information for Chrome, Firefox, Microsoft Edge, or Opera. It does not copy details from the browser you use to open Homebridge.

- **Offline fallback** — If the current version cannot be fetched, the wizard uses its last verified local version or the browser-version snapshot included in the installed plugin.
- **Persistent identity** — The generated <Terminology title="An ID for your device that the portal needs to log in" to="/docs/reference/terminology#setup-and-login">fingerprint</Terminology> is saved to `config.json` after setup; later browser releases do not change it automatically.
- **Portal device name** — The new trusted device appears as `<Homebridge instance name>.<UUID>`. The unique ID avoids timestamp-based name collisions, and the portal still rejects duplicate names.

## The `fingerprint` Field

The generated value is stored in the `fingerprint` field of the ADT Pulse <Terminology title="This plugin's settings object in config.json" to="/docs/reference/terminology#plugin-configuration">platform block</Terminology> in your `config.json`.

| Field         | Description                                                                                                                                                                                                                                                                                                                                                                |
|---------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `fingerprint` | The device <Terminology title="An ID for your device that the portal needs to log in" to="/docs/reference/terminology#setup-and-login">fingerprint</Terminology> generated by the <Terminology title="Logs into the portal for you and writes the plugin config" to="/docs/reference/terminology#setup-and-login">setup wizard</Terminology> and used to log in. Required. |

Here is where the field sits within the <Terminology title="This plugin's settings object in config.json" to="/docs/reference/terminology#plugin-configuration">platform block</Terminology>:

```json title="config.json"
{
  "platforms": [
    {
      "platform": "ADTPulse",
      "name": "ADT Pulse",
      "subdomain": "portal",
      "username": "user@example.com",
      "password": "Mys7r0nG!P@ssw0rd",
      "fingerprint": "VGhpc0lzQVNlY3VyZVBhc3N3b3JkMTIzIQ=="
    }
  ]
}
```

## Generating a New Fingerprint

If you need a fresh <Terminology title="An ID for your device that the portal needs to log in" to="/docs/reference/terminology#setup-and-login">fingerprint</Terminology>, re-run the <Terminology title="Logs into the portal for you and writes the plugin config" to="/docs/reference/terminology#setup-and-login">setup wizard</Terminology> and save its configuration. This replaces the old value only when you save.
